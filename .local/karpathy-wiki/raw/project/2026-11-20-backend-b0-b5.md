## Implemented

Backend-only extension; no Razor/CSS/JavaScript/Compose/assets/navigation changes. Existing finance/support/announcement data, migrations, opaque bearer tokens, stock ledger/atomic writes, rowversions, partial harvests, private photos and offline payloads are retained.

B0: tools/SmartFarm.DemoSeeder is an explicit Development/loopback console operation, never startup seeding. Fixed IDs and a serializable transaction prevent overwrite on repeat. Accounts use individually generated passwords stored only in an exclusive private credentials file. Current invitations remain retired; pending farm-code approval is seeded. Dataset has three farms including an empty farm, four identities (owner/manager/worker/applicant), role membership, plots and planned/active/completed crops, due/overdue/upcoming/completed tasks, field activity/observation, balanced low stock, multiple partial harvests in kg and bunches, synthetic weather/advisories and read/unread notifications. Optional monitoring photos require an explicit local source and private storage root.

The full EF model/catalog comparison expects 29 tables, 256 columns, 53 foreign keys, 48 checks and 60 indexes. The populated local SmartFarmDB target was verified read-only on loopback port 14333 in Development. It has 11 contract differences: five CropObservation columns (FollowUpStatus, FollowUpTaskId, IssueCategory, IssueSeverity, RowVersion), its follow-up FK/index and issue check, two FarmJoinRequest checks and Notification type check. No backup, seed rows, schema change or migration-history change was applied to that populated target. Alignment requires separate review. The verifier gained tested exact-type/range handling for equivalent integer CAST/CONVERT default expressions.

A separate disposable SmartFarmEnrollmentBackend_ database matched the complete model. BACKUP DATABASE COPY_ONLY WITH CHECKSUM and RESTORE VERIFYONLY WITH CHECKSUM succeeded before applying 40 identifiable synthetic demo records. Repeat application preserved existing records. This is not a restore rehearsal. A loopback API verified real seeded logins and farm isolation: owner three farms, manager two, worker two, applicant zero. No Worker execution or new business writes were performed by that live check. No photo source was supplied for this disposable seed.

B1: FarmTime preserves UTC instants and farm-local dates, with Asia/Manila default and configurable valid zones. API DTO/new sync-result timestamps have Z; historical sync ledger JSON is replayed byte-for-byte as stored and may contain zone-less UTC. New date-filter bounds handle missing/repeated midnights and skipped dates. Worker scheduling retains strict invalid-zone rejection. English/Filipino preference persists in existing Identity claims, with bilingual message catalog and additive stable error/status codes. Paged /records endpoints cover tasks, activities, observations/private photo metadata, harvests, inventory/movements and owner-only members/enrollment. Notifications have a complete paged read. Bounded page sizes, literal search, filters, totals and ID tie-breaks retain old routes and sync contracts. Offset pages must refresh after mutations; they are not sync cursors.

B2: saved-weather categories recent/active/upcoming/resolved/history preserve provider/retrieval/date/freshness and synthetic flags. All are forecast-based, not official warnings. Existing deterministic thresholds, missing-reading safety, dedupe and Hangfire schedules remain. Ani alerts reuse notifications with priority, farm/task/weather destinations, localization and read acknowledgment. Routine, resolved, stale, missing-source, past-date and synthetic notifications cannot trigger important interruptions. Shared notification visibility also protects legacy routes after membership removal and stock alerts after manager demotion. No duplicate notification table or new schema was introduced.

B3: disabled/default, Development capture and configured TLS SMTP senders; validated configured reset origin; isolated one-hour Identity reset tokens; neutral forgot/reset contracts; IP and bounded per-email throttle; MVC antiforgery form metadata/actions. A bounded 100-item background handoff performs account lookup/token generation/delivery after the public response, preventing account-dependent SMTP timing. Queue items expire after two minutes; queue and throttle are transient per process. Reset rotates stamps; API access/refresh and Web cookies revalidate them. MFA remains separate. Email templates are English/Filipino with Philippine timestamps; logs omit recipients/tokens/passwords. Actual SMTP delivery is unconfigured/unverified. Frontend owns forms.

B4: fixed-origin HTTPS Gemini generateContent adapter, private key/configured model, structured catalog composition, input minimization, timeout/no retries, bounded responses, daily per-process budget and one-hour/256-entry cache. Canonical crop/lifecycle/plot area/historical observation codes+time are permitted; raw farm/crop/plot names, notes, identities, coordinates, photos and arbitrary growth text are excluded. Provider output selects only fact-compatible bilingual explanations/recommendations, preventing invented dosages/readings and emergency severity changes. Stale/synthetic/resolved/unavailable forecasts bypass the model; all failures use deterministic guidance. No farm records or task/inventory/harvest decisions are changed automatically. No Gemini model/key or real provider call is verified.

## Executed verification

B0 solution check including new seed tests: 608 .NET tests passed, but conditional SQL suites had no connections and did not exercise SQL. B1: 616, B2: 618, B3: 631, B4: 640 .NET tests passed with strict disposable SQL, zero failures/skips.

Final B5 Release tests: 649 passed, zero failed/skipped (147 API, 390 Auth, 21 schema, 37 weather, 54 Worker). Both SMARTFARM_TEST_CONNECTION and SMARTFARM_ENROLLMENT_TEST_CONNECTION pointed only to disposable catalogs and SMARTFARM_REQUIRE_SQL_TESTS=1. Full Release build includes the demo seeder. Existing analyzer/deprecation warnings remain.

Python schema verification tests: 17 passed. Photo backup script tests: 7 passed. Node web regression tests: 90 passed. Android debug build, 78 JVM tests and instrumented-test compilation passed, zero JVM failures/skips. No physical-device/emulator execution, visual redesign, real-provider requests, populated Worker run, production deployment or full restore rehearsal was performed.

One independent whole-branch source/caller review found no Critical issues and identified provider stream fallback, DST midnight bounds, SMTP timing and new sync-result UTC coverage. Reproducing tests failed before the fixes; final Release suite passed after them. Guidance SQL fixtures were isolated from repeated/parallel test data. A 230-row tied-date paging case verified complete distinct pages, totals, last page and repeat order. Legacy ledger JSON remains unchanged on replay.

## Delivery limits

Draft PR targets dev, never auto-merge. Code/local verification does not establish release readiness. The populated local database still needs reviewed schema alignment before seeding, SMTP/Gemini need real configuration and controlled verification, the email queue/budget/throttle are per-process and transient, and frontend presentation remains independently owned. No new migration or dependency was added.
