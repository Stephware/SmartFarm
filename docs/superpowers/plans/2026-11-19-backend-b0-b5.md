# AniGo backend B0–B5 implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline, with tests per phase and a final whole-branch review.

**Goal:** Complete the backend contracts, safe demo preparation, localization, paged reads, alerts, account recovery and optional Gemini guidance required by the independent frontend.
**Architecture:** Extend the existing Core contracts and shared Infrastructure services. Keep existing API routes and offline envelopes; introduce additive paged endpoints. No frontend edits or startup database mutations.
**Tech Stack:** .NET 10, EF Core SQL Server, ASP.NET Core Identity opaque bearer/cookies, Hangfire, built-in HTTP/SMTP clients.
**Spec:** [User implementation request](../specs/2026-11-19-backend-b0-b5.md).

## Global constraints

- Feature branch from fetched `origin/dev` (`6fbd0a07`), Draft PR to `dev`, no merge.
- Preserve permissions, SQL-first history, rowversions, atomic stock, partial harvests, private photos and offline payloads.
- No Razor/CSS/JS/Compose/assets/navigation changes. Existing retired invitation links remain retired.
- Demo execution requires an explicitly verified loopback Development target, successful backup and schema comparison; no existing records overwritten.
- Provider integrations disabled until configured; no invented live-provider success.

## Review focus

- Pagination never caps offline synchronization or existing list routes; ties use IDs and totals use the same filters.
- Removed membership must prevent alert/guidance disclosure even with an old notification.
- Unknown weather readings and stale forecasts must not clear warnings or generate current-condition claims.
- Password-reset reuse, hostile origins, enumeration and old refresh/access tokens need explicit tests.
- Provider responses are untrusted; malformed, unsafe, unavailable and quota-limited outputs fall back without changing severity or records.
