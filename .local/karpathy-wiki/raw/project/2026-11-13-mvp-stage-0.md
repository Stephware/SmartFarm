The user requested farmer-first MVP implementation stage by stage. The product and execution plan are approved direction, not delivered functionality. Stage 0 inventories dependencies; no application code or schema changes are made.

Current MVC has nine farm links. Target: Today / Crops & Calendar / Supplies / Harvests. Android target: Today / Record / My Farm. Existing navigation, plot/history, finance, support and announcements still have callers; retire presentation only after replacement/dependency checks.

FarmFinanceController in Web and API calls IFarmFinanceService. Android FarmInsightsApi still calls reports/harvests and finance/insights, wired through repository, ViewModel and AppContainer. This is an active compatibility boundary. SyncOperationsController accepts activity, activity_stock, observation, inventory, harvest; finance is not a sync operation. Keep Room receipts, private photos, session guards and Worker scheduling.

Retain SQL tables, EF mappings/snapshot and migration history for finance, support and announcements alongside required farm records. No production records were inspected or changed; no DDL ran. Test SQL used only a separately initialized disposable catalog with an enforced test-name guard.
