# AniGo carabao onboarding — Phases 1–8 review

> **Current production implementation (November 2026):** The earlier Compose Canvas mascot described below has been replaced by the user-approved, image-based WebP sprite atlas with walking and talking frames, plus a separate Welcome slide. For definitive current implementation details see [`ANIGO_IMAGE_MASCOT_IMPLEMENTATION.md`](./ANIGO_IMAGE_MASCOT_IMPLEMENTATION.md). Historic phase notes are retained for traceability.

## Scope and review workflow

This branch implements the approved carabao-guided Android onboarding without changing the web UI, authentication, API, or farm database. Phase 7 adds only a local completion preference for the instructional walkthrough.

- Phase 1: `AniGoCarabao.kt` contains a reusable, native Compose Canvas carabao illustrated in six expressive poses: `WAVE`, `GUIDE`, `PLANT`, `RECORD`, `HARVEST`, and `CELEBRATE`. All poses share the same straw hat, cream horns, brown fur and green AniGo bandana. `frame = 0..3` drives the original arm/gesture variations; optional `walking` switches on alternating leg steps during the intro. All four pages use the same bounded vector frames; the motion is now synchronized with actual teaching milestones rather than continuous movement.
- Phase 2: `AniGoOnboardingScreen.kt` uses four swipeable learning pages, the existing AniGo logo, progress segments, a responsive field illustration, sample UI feature cards, Back / Next / Skip, and a final Continue button. Content is entirely illustrative and explicitly labeled.
- Entry: **new installations automatically start** in the guide's one-shot intro and four teaching pages. Completing the final page, pressing Skip, or leaving via Android Back from page 1 marks the guide complete locally and routes to the existing Welcome screen. Subsequent launches start normally at Welcome. On Welcome, **Explore AniGo with our farm guide** remains an optional replay. Signed-in users can replay via **My Account → Help & onboarding → Replay AniGo guide**, which returns to My Account without logging out. Login, registration, diagnostics and current welcome photograph remain untouched.
- Light and dark themes follow the existing `LocalFarmAppearance` setting. Guide copy and controls scroll/fit on compact phones and larger accessibility text. At 320dp width or 1.45× text scale, the illustration and teaching card stack vertically rather than overlapping.
- Phase 3: `AniGoFarmIntro.kt` runs a **single 2.55-second animated scene** when the opt-in guide opens: a carabao walks across a layered field, alternates native vector step frames, stops, waves, and the AniGo logo/headline fade in. An explicit **Skip intro** button or Android Back key immediately opens page 1. The sequence has no repeating loops or remote media.
- If Android's global animation duration scale is disabled, the introduction is bypassed and page 1 is shown directly. Intro completion is saved across configuration changes in the guide via `rememberSaveable`; there is no first-launch persistence yet.
- Phase 4: `AniGoFeatureDemos.kt` provides two bounded, self-contained teaching animations. **Farm management:** a sample Riverside Farm workspace appears, followed by North Plot, South Plot and team context; the carabao performs small guiding gestures. **Crop planning:** a rice crop plan progresses through Plan → Plant → Grow, with a small seedling growing while the carabao makes subtle planting gestures. Each page runs once after becoming active; off-screen animations cancel, revisiting the page restarts its demo, and an accessible **Replay example** action appears if motion is allowed. OS reduced-motion mode instead immediately shows the complete static sample, without a misleading Replay control. These are illustrative Compose components and **do not create farms, plots or crop calendar records**.
- Phase 6: `AniGoGuideMotion.kt` centralizes 2.1-second lesson timing, event-aligned gestures and a neutral final mascot pose. The guide now uses a 240ms intro-to-page fade, animated settled-page progress markers, and guarded navigation. Android's native Back key goes to the preceding slide before exiting at the first slide; Skip/Continue exit only once to the original Welcome screen. Animation pauses in the background and resumes at the remaining duration instead of looping/restarting; off-page lessons are cancelled. Buttons are disabled while pager scrolling settles. A dedicated 320dp / 1.6× text layout prevents the sample record card from obscuring the mascot or clipping content. Each slide resets its scroll position to its heading when revisited, especially important in the stacked large-text layout. Unit and instrumentation tests cover these behaviors.
- A single carabao vector implementation is intentional: do not use per-page separately generated character PNGs, which can introduce inconsistent horns, hats, eyes or scale. Inspect the **actual emulator rendering** against the approved reference before wider animation rollout.

## Verification criteria

1. Android debug compile, Compose UI test compile, unit tests.
2. Real emulator: intro Skip/Back, all four teaching pages, swipe and buttons, native Android Back through the pages, guarded Skip/Continue returning to Welcome, no auth regressions. All four demo sequences, replay, pending-sync wording, summed partial harvests, and reduced-motion final states must also pass.
3. At 320dp width and 1.6× font size, accessible controls stay visible and descriptive content remains scrollable.
4. Review artwork at 320dp and normal device widths; check horn/hat/body/prop alignment and dark-mode contrast.
5. First-launch routing must show the guide only until Skip/Continue/Back completes it, then always show Welcome on subsequent launches. Replays from Welcome or My Account return to their originating screen without resetting completion. Signing out does not trigger the guide again. Preserve the `WelcomeScreen` default callback contract and existing auth flows.

**Artwork note:** Phase 1 is a first native vector interpretation of the approved reference, not an exported/cropped copy of the user's previous generated raster mockup. Intro motion now uses that geometry; its final visual approval is still needed before animating or promoting it into other pages.

## Final refinement

The final pass integrates current dev auth/logo and regression fixes, preserves the six shared character poses, adds restrained palette shading, uses charcoal theme roles for dark samples, and compacts short-window layouts without shrinking touch targets. Reduced-motion paging is immediate and returning from system settings refreshes the animation preference. Background/resume, swipe/recreation, first-run persistence and both replay routes have focused regression coverage. The original Phase 8 screenshot export verified 24 fresh PNGs; the subsequent illustrated Step 5 audit now verifies 30 PNGs and 56 device tests. See the audit and PR #145 for exact-head results and remaining visual/device limits. No original approved reference artwork was available to establish an exact visual match.
